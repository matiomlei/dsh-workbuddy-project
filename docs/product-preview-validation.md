# 产品预览验证记录

版本：`dsh-workbuddy-project@0.4.0-preview.7`。日期：2026-10-22。

## 已验证

环境：macOS、Node.js 25.6.1、DSH npm 版本 `0.2.1-rc.2`、Git 2.23.0。验证 profile 使用独立 `DSH_HOME`，没有覆盖日常 DSH。

- 既有能力包与库同步单元检查通过。
- 真实 DSH 宿主能力管理检查通过，覆盖 HTTP/stdio MCP 调用、能力保存和 preset 生命周期。
- 移入发布包的模板、Git 交接、质量账本与恢复检查点 29 项回归检查通过。
- 离线包制作成功：包含普通 JS/WASM 依赖和预编译画布，无 `.node` 原生模块、无符号链接；宿主 peer 不混入包。
- 用安装 helper 在新的 profile 中解压、合并配置、检查 DSH 精确版本，并通过链接复用同一份宿主依赖。安装后的产品入口和画布可打开。
- 使用仅在测试目录内注册的确定性模型适配器，经真实 DSH Agent、工具与文件策略完成：能力内容快照 → 发布 v1 → 绑定项目 → 编码文件 → 节点待验收 → 人工通过 → 下游读取代码并形成测试记录 → 汇总结束。
- 共享能力库的专家和规范进入节点上下文；绑定的 Skill 经真实 `skill` 工具成功加载，MCP 经真实 DSH MCP 客户端完成调用。显式只选择 read/write/skill 时，绑定 MCP 仍可调用。测试 MCP 与模型均仅在独立测试目录注册，没有调用外部模型。
- 画布基础工具列表与运行范围一致，不再包含 working_directory 等不可用项；运行固定 DSH 选择的 provider/model，产品代码不强制使用测试模型。
- 下载累计补丁后，在全新 clone 中 `git apply --check`、应用并用 Node 执行生成代码成功。源仓库提交和工作区保持不变。
- 发布 v2 后，项目绑定与旧运行仍固定 v1。
- 浏览器验证四个产品入口、草稿画布保存和验收操作；补验节点面板四类能力入口、分类选择器及多条规范保留快照的重新保存。截图保存于 `docs/screenshots/`。

正常路径自动化脚本及重现步骤见 [发布验证](releasing.md)。一次完整检查结果保存在隔离环境的 `acceptance-report.json`；不把该环境的本机路径或会话数据打进安装包。

## 标准研发模板验证

本版另外验证内置需求→设计→编码→测试模板。四个阶段分别加载绑定能力，经本地仓库 MCP 读取实际上游文档；每阶段固定报告后验收放行。编码与测试 Agent 通过 DSH bash 实际执行 7 项测试，累计补丁在新 clone 中应用后复测仍为 7 通过、0 失败。模型决策为测试适配器，未调用外部模型。详情见 [模板说明](software-delivery-starter.md)、[执行记录](validation/software-delivery.json) 和 [复测输出](validation/software-delivery-tests.txt)。

## Windows 路径回归

针对 Windows 实机反馈的包路径错误，使用 Windows 路径语义和映射文件系统运行实际能力包扫描代码：修复前复现原报错；修复后，盘符、中文/空格路径中的专家元数据、附带 Skill、引用文件和 MCP 包读取通过，内容哈希与本机扫描一致。绝对路径和越界引用仍被拒绝。此项是 Windows 路径语义验证，不是 Windows 系统实测。

## Windows 模块导入与离线字体

本地复现 Node 将原生 Windows 盘符路径解释为 URL 协议的失败。四阶段真实编译结果中的节点规范与连接器入口均检查为存在的 file URL；模块缺失的诊断保留组件名及原始错误码。安装验证还检查画布实际 CSS 响应不包含 Google Fonts 外网导入。另核对画布初始化所查询的工具、技能、模型、运行时、凭据和运行列表接口；用户反馈的 lark-auth 400 已改为明确的未启用响应。Windows 系统本身仍需实测。

## 本轮 Windows 路径检查

preview.6 扩展原生路径范围、目录身份、Git 地址及本地 MCP 入口的回归。真实 Git 同步采用中文/空格源路径；离线自检在特殊字符目录内编译四阶段能力、导入组件、处理超过 260 字符路径、调用 MCP 并交接代码。检查范围和目标机命令见 [Windows 路径检查](windows-path-audit.md)。隔离安装后的[自检输出](validation/windows-path-smoke-macos.json)明确标记 `nativeWindows: false`，不冒充 Windows 实测。

## 节点对话与运行过程

preview.7 的真实 DSH 隔离安装验收覆盖：模型思考在流式生成完成前经认证接口可见；运行中补充指令只接收一次；人工回答等待超过节点超时仍可继续；验收前对话生成第二次执行及新产物，旧验收不能放行；新结果通过后下游读取 v2；已完成节点只读讨论不改变固定结果；等待用户时取消能释放会话。测试使用仅在测试目录注册的确定性模型适配器，无外部模型调用。[本轮交互验证记录](validation/node-dialogue.json)。
