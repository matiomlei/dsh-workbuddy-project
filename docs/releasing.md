# 发布准备

本目录可直接作为 `dsh-workbuddy-project` 仓库根目录。版本沿用当前实现的 `0.3.0`，这不是已发布或完整市场验收的声明。

## 仓库与待补材料

- 仓库：https://github.com/matiomlei/dsh-workbuddy-project；package.json 已配置 repository、homepage、bugs，README 已提供仓库安装命令。
- 提供「项目」「能力库」截图及一个完整演示：安装 → 创建项目 → 应用 → 新会话使用。
- 根据选择的 DSH 社区市场核验收录与元数据规则，并填写插件描述、分类及兼容范围。
- 如果要发布 npm 包，使用有发布权限的账号，确认包名仍可用后执行发布。

建议简介：为 DSH 按项目配置专家、技能、规则与连接器，复用项目模板，并可接入共享能力库。

建议分类：项目管理、工具与能力、工作流。

## 验证

```sh
npm test
npm run test:host
npm run test:ui
npm run check:package
npm pack
```

`check:package` 校验 npm 实际收录文件、入口文件、包名、许可和文档，拒绝把用户数据、依赖目录或开发测试装入 npm 制品。测试目录和 scripts 在仓库中保留，用于开发验证。

宿主测试使用临时目录、回环 MCP 服务和临时 Git 仓库，可验证宿主加载、连接器和能力包操作。页面测试使用 jsdom。它们不能代替以下真实安装验收：

- 独立干净 profile 从 tgz 安装，确认「项目」「能力库」入口和 `/project` 可用。
- 未配置资源库、平台账号和 projectsRoot 时可创建仅含指令的项目；数据写入 DSH 用户目录。
- 选择示例模板，保存编译后，在完整 DSH 新会话中检查实际加载内容。
- 重启后项目仍可用，旧会话不被配置修改替换。
- 升级保持项目和锁定能力；卸载保留用户工作目录、库和项目源文件。
- 检查窄屏、亮色/暗色，以及缺失依赖、连接器授权失败、Git 同步失败的提示。

通过这些验收、补齐截图后，再标记为正式发布。当前不包含公司内部平台、账号系统或多人项目协作。

## 独立开发

初始内容由上级开发仓库 `scripts/release/prepare.mjs` 生成。本仓库可独立维护，不需要该生成器或父目录。

生成器重复执行会校验已有文件，不会静默覆盖在本目录做的修改。后续同步开发目录的修复时，应逐项合并并重新验证。
